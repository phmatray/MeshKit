# MeshKit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A deployable SaaS that sells packs of Meshy-generated 3D models through Stripe Checkout, with the packs produced by a GitHub Actions pipeline.

**Architecture:** Four projects — `Core` (pure domain: pack definition, manifest), `Meshy` (typed HttpClient), `Pipeline` (console tool driven by the workflow), `Web` (Blazor SSR store + Stripe + catalog). The catalog is a directory the pipeline fills and the web app reads; the DB holds only users, orders and entitlements.

**Tech Stack:** .NET 10 (SDK 10.0.400), Blazor Web App (static SSR), EF Core 10 + SQLite, ASP.NET Core Identity, Stripe.net 52.3.0, YamlDotNet 18.1.0, Tailwind v4 + `@google/model-viewer` via npm, xunit 2.9.3, Docker multi-stage, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-08-22-meshkit-design.md`

## Global Constraints

- TFM `net10.0` everywhere; nullable + implicit usings on; portfolio `.editorconfig` (warnings never errors).
- Branch `main`; MIT licence; renovate extends `local>phmatray/.github:renovate-ci`.
- Stripe: `StripeClient` instance only, API version `2026-07-29.dahlia`, never `payment_method_types`, fulfil only from webhook, idempotent on `session.id`.
- Meshy: `MESHY_API_KEY` from env only; base `https://api.meshy.ai`; endpoints `/openapi/v2/text-to-3d[/{id}]`; statuses `PENDING|IN_PROGRESS|SUCCEEDED|FAILED|CANCELED`.
- Manifest paths relative to the pack dir, confined to `public/` or `private/`.
- Never build in a copy of another repo; every task ends with `dotnet build` + `dotnet test` green and a commit.
